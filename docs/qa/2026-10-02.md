# Preview QA — 2 October 2026

Tested **2.1.0-preview.1**, main commit `d004e01`, on Windows 11 in an isolated
`main-qa` profile. The user's default settings were not changed. Computer Use drove
the visible host UI. No application source changed during this documentation pass.

## Verified behaviour

| Scenario | Result |
| --- | --- |
| Open contextual editing above occupied panes | Toolbar and **Ctrl+Alt+E** work without exposed background; last-used app is selected |
| Split occupied Notepad in a two-column layout | **H** adds rows and **V** splits its selected child; Notepad and Explorer remain hosted |
| Change the editing target | Clicking Explorer and using arrow keys changes the labelled/tinted target |
| Split the other occupied app | **H** splits Explorer without changing Notepad's nested layout; five zones, two apps |
| Finish editing | **Enter** returns focus to the selected app; both apps remain hosted |
| Join an occupied pane to an empty neighbour | **J → Join down** expands Explorer; three zones become two, still two hosted apps |
| Change presets with occupied panes | Two side-by-side and Big left, stacked right retain both hosted apps |
| Use a hosted app | Explorer's address bar navigates to the repository; Notepad's test text stays intact |
| Focus next/previous | Temporary **Ctrl+Alt+F1/F2** bindings move between Notepad and Explorer; accessibility focus and the background tint follow |
| Change focus colours | Blue → green `#7EE787` → blue applies immediately; green status/primary-button text uses readable dark text |
| Change themes with hosted apps | Dark Modern → Light Modern → High Contrast → Dark Modern retains both apps; native app themes remain independent |
| Command palette | Title-bar search opens the palette above the hosted apps; **Esc** closes it without a layout change |
| Remove an occupied zone | Removing Calculator, then Character Map releases those apps and preserves the remaining hosted apps |
| Calculator after release | The released Calculator renders its normal keypad again |

All nine default command bindings were restored after testing. The QA-only
workspace binding remains **Ctrl+Alt+F9**. Fancy Window was left open in Dark Modern
with the blue accent and Notepad/Explorer hosted.

## Compatibility failures

**Calculator renders blank while hosted.** In a four-app layout, its pane remained
blank at both normal and maximized host sizes. The contextual editor still named
Calculator and counted it as hosted. Removing its zone released it; its normal UI
then rendered again. This is a hosting compatibility failure, not a passed
Calculator test. Reproduce with the installed Windows Calculator alongside Notepad,
Character Map and File Explorer, then compare hosted and released states. No fix
or root cause is claimed here.

**Clipping and repaint strips remain.** Character Map clips in small panes; at a
larger host size its content appears but black/frame strips remain. Notepad and
Explorer also showed stale edge content after some resizes. This is relevant to
the existing [black-strip issue #7](https://github.com/DevNickThomas/FancyWindow/issues/7).
Small panes can make native controls unusable even when the layout operation itself
succeeds. Minimum-size handling and frame repainting need further investigation.

## Coverage limits and remaining checks

- Four real apps were observed hosted together after assisted attachment. The
  exact Alt+mouse-drag-in/out gesture is **not signed off**: the available drag API
  cannot hold Alt during a drag. A keyboard Move/Alt+Enter attempt did not reliably
  release an app. Release through Remove zone is verified separately.
- A normal title-bar drag of hosted Notepad left it in its pane with the hosted
  count unchanged. The invisible intermediate drag path was not verified.
- The occupied vertical-splitter drag was **inconclusive**: Computer Use reported
  the exposed-gap coordinate as belonging to Notepad, including after a fresh
  capture and retry. This does not establish an application splitter defect.
- Exact default **Win+Alt** chord delivery still needs manual testing. Computer
  Use's Windows-key restriction required temporary Ctrl+Alt bindings. Registration
  and the command actions were checked separately.
- Custom invalid-hex input was not completed because the tool could not resolve
  the observed edit control. Swatch changes and theme switching were tested.
- Windows 10, mixed-DPI transitions, multiple-instance arbitration, repeated
  drag-out/reattach loops, and unsaved-document behaviour need additional coverage.

Suggested next manual pass: Alt+drag each app in, out and back in twice; resize
occupied splitters; repeat the nested-split sequence; cycle focus with the default
Win+Alt chords; then close the host and confirm every app survives. Keep Calculator
and frame-strip findings open until retested with a fix.
